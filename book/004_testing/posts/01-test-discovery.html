pytest のテスト探索規則

pytest は以下の標準的なテスト探索を実装しています．

  • 引数が指定されない場合，収集は testpaths（設定されている場合）またはカレントディレクトリから開始されます．また，コマンドライン引数としてディレクトリ・ファイル名・ノード ID を任意に組み合わせて指定することもできます．
  • norecursedirs に一致しないディレクトリに再帰的に入ります．
  • 対象ディレクトリ内で test_*.py または *_test.py にマッチするファイルを，テストパッケージ名としてインポートして検索します．
  • 対象ファイルからテストアイテムを収集します：
    • クラスの外部にある test プレフィックスのテスト関数またはメソッド
    • __init__ メソッドを持たない Test プレフィックスのクラス内にある test プレフィックスのテスト関数またはメソッド（@staticmethod や @classmethod でデコレートされたメソッドも対象となります）

テスト探索のカスタマイズ例については，標準的な Python テスト探索の変更を参照してください．

Python モジュール内では，pytest は標準の unittest.TestCase サブクラス化手法を使ったテストも探索します．

標準的な Python テスト探索のカスタマイズ

テスト収集時のパスの除外

CLI で --ignore=path オプションを渡すことで，収集時に特定のテストディレクトリやモジュールを簡単に除外できます．--ignore オプションは複数指定可能です．以下のようなディレクトリ構成を例とします．

tests/
|-- example
|   |-- test_example_01.py
|   |-- test_example_02.py
|   '-- test_example_03.py
|-- foobar
|   |-- test_foobar_01.py
|   |-- test_foobar_02.py
|   '-- test_foobar_03.py
'-- hello
    '-- world
        |-- test_world_01.py
        |-- test_world_02.py
        '-- test_world_03.py

--ignore=tests/foobar/test_foobar_03.py --ignore=tests/hello/ を指定して pytest を実行すると，指定したパターンに一致しないテストモジュールのみが収集されます．

=========================== test session starts ============================
platform linux -- Python 3.x.y, pytest-5.x.y, py-1.x.y, pluggy-0.x.y
rootdir: $REGENDOC_TMPDIR, inifile:
collected 5 items

tests/example/test_example_01.py .                                   [ 20%]
tests/example/test_example_02.py .                                   [ 40%]
tests/example/test_example_03.py .                                   [ 60%]
tests/foobar/test_foobar_01.py .                                     [ 80%]
tests/foobar/test_foobar_02.py .                                     [100%]

========================= 5 passed in 0.02 seconds =========================

--ignore-glob オプションを使うと，Unix シェルスタイルのワイルドカードでテストファイルパスを除外できます．_01.py で終わるテストモジュールを除外したい場合は，--ignore-glob='*_01.py' を指定して pytest を実行します．

テスト収集時のテストの除外

収集時に --deselect=item オプションを渡すことで，個別のテストを除外できます．たとえば tests/foobar/test_foobar_01.py に test_a と test_b が含まれている場合，--deselect=tests/foobar/test_foobar_01.py::test_a を指定することで test_a 以外の tests/ 配下のすべてのテストを実行できます．--deselect オプションも複数指定可能です．

コマンドラインで指定した重複パスの保持

pytest のデフォルト動作では，コマンドラインで指定された重複パスは無視されます．

pytest path_a path_a
# collected 1 item（1 回だけ収集）

重複したテストも収集したい場合は，--keep-duplicates オプションを使います．

pytest --keep-duplicates path_a path_a
# collected 2 items

ディレクトリ再帰のカスタマイズ

設定ファイルで norecursedirs オプションを指定できます．

# pytest.toml
[pytest]
norecursedirs = [".svn", "_build", "tmp*"]

これにより，pytest は Subversion や Sphinx のビルドディレクトリ，tmp プレフィックスのディレクトリに再帰しなくなります．

命名規則のカスタマイズ

設定ファイルで python_files・python_classes・python_functions を指定することで，異なる命名規則を設定できます．

# pytest.toml
# 例: "test" の代わりに "check" を探す
[pytest]
python_files = ["check_*.py"]
python_classes = ["Check"]
python_functions = ["*_check"]

この設定により，pytest は check_*.py にマッチするファイル，Check プレフィックスのクラス，*_check にマッチする関数・メソッドを探索します．たとえば次のファイルがある場合：

# check_myapp.py
class CheckMyApp:
    def simple_check(self):
        pass

    def complex_check(self):
        pass

収集結果は以下のようになります．

$ pytest --collect-only
=========================== test session starts ============================
...
collected 2 items

<Dir pythoncollection.rst-214>
  <Module check_myapp.py>
    <Class CheckMyApp>
      <Function simple_check>
      <Function complex_check>

======================== 2 tests collected in 0.12s ========================

スペース区切りで複数のグロブパターンを指定することもできます．

# pytest.toml
# 例: "test" と "example" の両方を探す
[pytest]
python_files = ["test_*.py", "example_*.py"]
ノート

python_functions と python_classes オプションは，unittest.TestCase のテスト探索には影響しません．pytest がテストケースメソッドの探索を unittest コードに委譲するためです．

コマンドライン引数を Python パッケージとして解釈

--pyargs オプションを使うと，pytest は引数を Python パッケージ名として解釈し，対応するファイルシステムパスを導出してテストを実行しようとします．たとえば unittest2 がインストールされていれば，次のように実行できます．

pytest --pyargs unittest2.test.test_skipping -q

設定ファイルの addopts オプションでこの変更を恒久的にすることもできます．

# pytest.toml
[pytest]
addopts = ["--pyargs"]

収集対象の確認

テストを実行せずに収集ツリーを確認するには --collect-only を使います．

$ pytest --collect-only pythoncollection.py
=========================== test session starts ============================
...
collected 3 items

<Dir pythoncollection.rst-214>
  <Dir CWD>
    <Module pythoncollection.py>
      <Function test_function>
      <Class TestClass>
        <Function test_method>
        <Function test_anothermethod>

テスト収集のカスタマイズ

すべての Python ファイルからテストを探索させることもできます．

# pytest.toml
[pytest]
python_files = ["*.py"]

ただし，多くのプロジェクトにはインポートされたくない setup.py などのファイルが存在します．また，特定の Python バージョンでしかインポートできないファイルがある場合もあります．そのような場合は，conftest.py にリストアップすることで動的に除外できます．

# conftest.py
import sys

collect_ignore = ["setup.py"]
if sys.version_info[0] > 2:
    collect_ignore.append("pkg/module_py2.py")

Unix シェルスタイルのワイルドカードで除外する場合は collect_ignore_glob を使います．

# conftest.py
import sys

collect_ignore = ["setup.py"]
if sys.version_info[0] > 2:
    collect_ignore_glob = ["*_py2.py"]

__test__ 属性による探索の抑制

pytest 2.6 以降，__test__ 属性を False に設定することで，Test で始まるクラスの探索を防ぐことができます．

# テストとして探索されない
class TestClass:
    __test__ = False

抽象テストクラスを扱う際にサブクラスで __test__ を手動設定したくない場合は，ミックスインクラスを使う方法があります．

# 抽象テストクラスを扱うミックスイン
class NotATest:
    def __init_subclass__(cls):
        cls.__test__ = NotATest not in cls.__bases__


# 抽象テストクラス
class AbstractTest(NotATest):
    pass


# テストとして収集されるサブクラス
class RealTest(AbstractTest):
    def test_example(self):
        assert 1 + 1 == 2

このアプローチにより，抽象テストクラスのサブクラスは __test__ 属性を明示的に設定しなくても自動的に収集されます．
